# Opt-in D-FINE training backend ("dfine-coco", projects/training/dfine.py). It runs on the four pins above and needs
# exactly ONE more package: scipy, because transformers' Hungarian matcher (used by the D-FINE training loss)
# raises "RTDetrHungarianMatcher requires the scipy library" without it. Not needed: timm, accelerate (checked), and torchvision is not touched by this backend (the D-FINE
# training tests pass with torchvision blocked; the torchvision backend still needs it).
# Exercised on Python 3.14.4 in a venv with numpy 2.3.2 (the version its install log shows), NOT with the numpy pin above:
# numpy==2.5.5 has no cp314 wheel on the index used, and the other worker venv here that reports 2.1.3 on Python 3.14.4
# was compiled from source on that machine (wheel tag macosx_27_0), not installed from a published wheel. On Python 3.14
# the numpy pin above may therefore need raising (2.3.2 is the version that was seen to work). scipy 1.18.1 requires
# numpy>=2.0,<2.8, so it fits both. Licence: BSD-3-Clause; its macOS wheels
# also bundle libgfortran (GPL-3.0-or-later WITH GCC-exception-3.1) and libquadmath (LGPL-2.1-or-later): list it in
# docs/LICENSE_AUDIT.md before shipping.
scipy==1.18.1

# Audio classification backend ("audio-wav-cnn", projects/training/audio_wav.py; added 2026-11-19). Needs nothing
# beyond the four pins above (torch, numpy) except ONE OPTIONAL package: onnxruntime. With it installed the trained
# clip classifier is exported to an ONNX graph and predictions run through onnxruntime's CPUExecutionProvider;
# without it the backend saves a torch state-dict artifact and predicts through torch (the tests cover both paths;
# the real separable-frequency training run used the venv that has it). Not needed: librosa (checked — the mel
# spectrogram is computed with numpy directly), soundfile (WAV validation is stdlib `wave` in the web process).
# Licence: MIT. Version shown is the one the ML venv that ran the audio tests had. Listed in docs/LICENSE_AUDIT.md
# (addendum 2026-11-19; the binary wheel's bundled notices were not read there).
onnxruntime==1.20.1

# Handwriting OCR backend ("ocr-trocr", projects/training/ocr_trocr.py; added 2026-11-19). Runs on the pins above

# own code over transformers' TrOCRProcessor / VisionEncoderDecoderModel. The base weights

# Excel-reading half of the tabular-prediction backend ("tabular-sklearn", projects/training/tabular_sklearn.py;

# as the engine, and NOTHING else in this tree imports it (checked 2026-11-19): CSV table training, the other four
# backends and the web process all run without it. Without openpyxl an .xlsx run fails in plain words at the read
# step, telling the operator to install it or upload a CSV. Licence: MIT (read from the installed
# openpyxl-3.1.5.dist-info METADATA, which says `License: MIT` and carries the MIT classifier; the dist-info also
# ships LICENCE.rst, the same text). Its one transitive, et-xmlfile (MIT), comes with it. Listed in
# THIRD_PARTY_NOTICES.md and docs/LICENSE_AUDIT.md (addendum 2026-11-19).
openpyxl==3.1.5
